# 派星文案检查

用于合生元派星婴幼儿配方奶粉 **2 段（适用 6-12 月龄）** 的小红书投放素材初稿审校。

**检查 → 修正**两个阶段。检查分词表层（脚本，确定性）和事实层（模型）；
修正按风险分三档，从「清单说了算」到「模型自己拿捏」，可信度依次下降。

## 安装后的文件定位

本 skill 的调用名为 `$paixing-copy-review`，中文名称为「派星文案检查」。

下文的 `check.py`、`verify.py`、`prompts/`、`tables/`、`examples/` 均相对于
**本 SKILL.md 所在目录**，不是用户稿件所在目录。执行时使用脚本绝对路径和稿件绝对路径；
Python 命令按当前环境选择 `python3`、`python` 或 Windows 的 `py -3`。
原稿、改稿、问题清单和验证输出保存在用户工作目录，不写入 skill 安装目录。

此分发版不包含真实稿件回归集。`examples/` 只有合成的安装验证样例，
不能作为真实消费者经历或产品效果素材。历史评测数字仅供了解原开发记录，
不代表当前词表下的检出率或效果承诺。

## 怎么执行

**不管用户怎么说，都从第一步开始按顺序跑完。**

用户通常只会说「帮我润色一下」「改一下这批稿子」，
**不要因此直接跳到润色**——那会漏掉事实矛盾和红线词。

```
1. check.py 词表校验        ← 脚本，必跑
2. 事实核查                 ← 硬矛盾：数字、月龄、时间线
3. 细节可信度               ← 软可信度：哪些细节是编的
4. 定点修正（按 1、2、3 的清单）
5a. 场景化                  ← 先动结构
5b. 口语化                  ← 后修措辞
6. verify.py 越界检查 + 重跑 check.py
```

每一步做完，简单报一句做了什么、发现几条，再进下一步。

**不要停下来等人确认。** 事实矛盾这类，两处数字都是写出来的，
模型自己选一个自洽的改法即可，记进 `changelog` 供人事后追溯。
只有改动会碰到**稿件设定本身**（人群、月龄、核心 msg）时才标出来
（`need_brief_decision`），那不是文字问题。

> ⚠️ **四步必须按顺序跑，不能跳。**
> 实测跳过事实层直接润色，漏掉了一篇「十罐、十个月、一个月一罐」——
> 按月龄换算应为八九天一罐，而同篇评论区还写着「一罐一个星期」。
> 润色只改措辞，抓不到这类问题。

## 第一步 · 词表层（必做，不需要模型）

```bash
python check.py 稿子.txt
python check.py 稿子目录/
python check.py 稿子.csv --column 初稿
python check.py 稿子.txt --json
```

无外部依赖，Python 3 标准库即可。检查四类：

| 层 | 内容 | 表 |
|---|---|---|
| 红线 | 病征词、药效词。奶粉不是药，不能把宝宝写成有病、把奶粉写成有疗效 | `tables/红线词.csv` |
| 平台卡审 | 实测会触发平台审核的词 | `tables/卡审词.csv` |
| 竞品表述 | 同一品牌在稿子里必须用统一写法 | `tables/竞品表述.csv` |
| 当期策略 | 已停用 / 当期主推的目标品牌 | `tables/当期策略.csv` |

**竞品表是多对多**：左边是已知的全部变体，右边是当期允许的候选。
脚本只报「用了不在候选里的写法」并列出候选，**不做自动替换**——选哪个是写作决策。

## 第二步 · 事实层（需要模型）

按 `prompts/事实核查.md` 执行，参考数值取自 `tables/月龄参考.csv`。

找的是**自相矛盾**和**与月龄常识不符**：起始月龄加喝奶时长对不对得上当前月龄、
单次奶量和罐消耗速度是否合理、体重身长是否匹配、出现的行为和生活场景是否符合月龄、
效果出现得是不是太快。

**三处容易漏，已写进 prompt：**

- **效果周期**：`tables/效果周期.csv` 列出了每种效果最早多久出现才可信。
  文中每出现一个「喝了 X 时间 + 出现 Y 效果」就查一次。
  实测漏过一处：`现在喝了一个月` 配「长肉、结实」，**人类编辑把它改成了三个月**。
  注意区分谁看出来的——自己摸出来 / 秤上看出来 / **外人看出来**，
  需要的时间依次变长。

- **罐消耗速度要动手算**，不能凭感觉：日均奶量 ÷ 100 × 13 = 日均耗粉克数，
  800 ÷ 日均耗粉 = 一罐几天。10 月龄约 8.8 天一罐，「一个月一罐」是错的。
- **正文和评论要一起喂、交叉核对**。这类稿件常配 20 条评论和对话块，
  正文说一套、评论说另一套是实际发生过的。

## 第三步 · 细节可信度（模型）

按 `prompts/细节可信度.md` 执行。查的是**已有细节里哪些一眼看着就假**，并且改掉。

**这一层只查六类能说清楚的，不追求把所有假的都找出来。**

| 类型 | 实例 | 假在哪 |
|---|---|---|
| 生造概念 | 什么**奶粉荒**都见过 / 冲得比我还**标准化** | 生造词、硬名词化 |
| 强行的金句 | 明年这时候，她喝奶该比我还准时了 | 对仗工整、语义不通 |
| 台词不真实 | 她感慨：还是你会偷懒 | 真人不会这么夸 |
| 常规操作被惊讶 | 冲完**还**往手腕上滴两滴试温 | 试温是常规，「还」字不成立 |
| 多人物指代混乱 | （三个对象后）**她倒好**，喝奶从来不用催 | 「她」指谁 |
| **元素之间不匹配** | 十个月「吃饱把碗一推就下地」／逛超市走生鲜区 | **配对检查**：场景↔宝宝、动作↔月龄、人物↔言行、影响↔原因 |

**为什么必须单独一层**：编造的细节大多很具体，所以能通过事实核查（数字没错）、
通过口语化（措辞很口语）、通过场景化（细节不缺）。三层都放行，读起来却一眼假。
第二类尤其——它措辞上很口语，**口语化那步不但抓不到，还会顺手把它润色得更顺**。

### 只查这六类，不追求查全

原本还有第六类「细节之间没有真实因果」，**试了四轮四种改法全错，已砍掉**——
判断"这个细节到底在解释哪件事"需要读懂全文语义，这个判据描述不清楚。
**判据说不清楚的就不要放进来**，查不准的改法只会越改越坏。详见 `失败记录.md`。

### 怎么改交给模型自己定

**不规定改法步骤。** 换说法、调语序、削半句、补个过渡，都行——
为了让改动读顺而加几个字是正常的，卡死了反而改不好。

改完之后只要满足两件事：

**一、这仍然是一篇完整的笔记**——有开头有落点，读下来不缺胳膊少腿。
无约束跑第一轮时模型倾向用「整句删掉」解决一切，
12 篇删出去 10.8% 的字、八篇的结尾没了：**问题消灭了，文案也废了。**
说清"要留一篇完整的笔记"比设一个删除比例上限管用——
**比例是我拍的数字，遇到假货特别多的稿子反而会逼它把假的留着。**

**二、拿这五条，再检查一遍它自己改出来的句子。**

这一条的写法很关键。直接说「别改出新的假细节」是**循环的**——
它要是能凭空判断什么是假的，第一版就不会写出假的来。
但让它**拿五条具体标准去检查一段给定的文字**，它做得到（这一层的检出准确率已证明）。
所以要求的是**用同一把尺子量自己的产出**，而不是要求它凭空更聪明。

> 实例：`她后来也想给娃转回来` → `想给娃换成这款`
> ——改写时替朋友做了一个原文没有的决定，正好踩中第三类
> （替人物补了一句他没说的话）。**五条自查就能发现。**

**这两条都是关于结果的，不是关于方法的**——实测证明约束结果能落地，
约束方法（规定必须按哪几步改）只会换一种错法。

## 第四步 · 定点修正（改稿主力）

按 `prompts/定点修正.md` 执行。输入是原文 + 前两步的问题清单，
**只改清单标出的位置，清单以外一个字不动**。

这一步风险最低，因为它没有自由度——**改哪里由词表和事实清单决定，不由模型决定。**

### 实测基线（4 篇，清单共 17 条）

| 指标 | 结果 |
|---|---|
| 总改动 | 19 处 |
| 越界（清单外的改动） | 4 处（21%），集中在一篇的结构化内容 |
| 修正后新引入的词表问题 | **0** |
| 修正后剩余的词表问题 | **0** |
| 自行编造数字 | **0** |
| 事实类取舍报备 | 7 条 |

**事实类的处理方式是这一步最值得信任的地方。** 清单只说「两处对不上」、
没说哪处是错的。**新版改为模型自己选一个自洽改法并记入 changelog**，不再阻塞：

> 「一星期喝完一罐」→ 整句删除，未替换成其他消耗速度。
> 是否需要补一个真实的消耗天数？如需要请提供，**我不自行编造数字**。

> 「9 个月大」与「喝了快 5 个月」矛盾 → 删去月龄保留时长。
> 是否确认以「喝了快 5 个月」为准？**若实际就是 9 个月大，则应改喝奶时长而非删月龄。**

越界的 4 处里 3 处来自同一篇：清单只说「转奶表第 13 天重叠」，
模型把整张表按规律重排并**新增了一行**。超出授权，但它主动报备了。
**结构化内容（步骤表、清单）容易诱发超范围改动，复核时重点看。**

### 改完必须做三件事

```bash
python verify.py 原文.txt 修正后.txt --findings 清单.json
```

1. **越界检查**：`verify.py` 逐处比对改动是否落在清单范围内，
   并检查是否引入新的词表问题。有问题返回非零退出码，可直接卡住流程。
2. **重跑 `check.py`**：确认清单上的问题都清掉了。
3. **扫一眼 `changelog`**：事实类模型自己选了改法，不阻塞，但要能追溯。
   只有 `need_brief_decision` 里的才需要写稿人决定。

### verify.py 的已知局限

**全篇一致性类的改动会被误报为越界。** 例如人称统一——事实清单只标出一处
「哄她喝了不少」，但要统一就必须同时改另一处的「他」，而那处不在任何区间内。
位置区间验证覆盖不了这类改动，看到这类越界需要人工判断，不要直接打回。

## 第五步 · 润色（场景化 + 口语化）

这一步是**文案润色**，分两个独立的 prompt，不要合成一次调用——
它们的约束方向相反：场景化**可以动结构、可以新增内容**，口语化**只改措辞、不许新增**。
混在一起，前者做不了、后者会开始编造。

**必须先场景化、后口语化。** 场景化会移动和增删句子（就地取材本质是把已有句子挪位置），
先润色了措辞，挪完之后衔接会断，补进来的内容也没被润色过，
一篇里出现两种质感。**结构先定，措辞后修。**

在定点修正之后跑，**不要撤销定点修正改过的地方**。

### 5a · 场景化 → `prompts/场景化.md`

**核心判据是「决定点必须有细节支撑」，不是"给文案多加生活场景"。**

文案里凡是出现要转、要换、不换、坚持喝、直接续——都是一个决定点。
每个决定点必须至少有一个直接相关的具体细节，落在决定的
**前**（什么逼出了这个决定）／**中**（对比过程遇到了什么）／
**后**（试过之后什么表现让你确认）任一环节。

**加得再多的生活场景，只要不落在决定上就是无效场景。**
实测这批稿件逛超市、淘气堡、阳台空罐写得都很生动，但「为什么不换」背后是空的。

**加细节最容易翻车的地方是引入新的不合理。** 实测出现过
「逛超市走到生鲜区她就往下坠」——生鲜区地湿有腥味，带娃本来会绕开；
而且"走到哪里"和"娃变沉了"没有因果关系。补之前必须过三关：
**真实吗 / 有关吗 / 合理吗**，任一过不了宁可不补。

**处理有优先级，一篇通常只动一到两处：**

| 优先级 | 发现什么 | 怎么处理 |
|---|---|---|
| 1 | 决定点缺支撑 | **先就地取材**——同篇里找已有的具体事实挪到决定旁边建立连接，不新增信息。就地没有再用素材；都没有就只标记，**不要编** |
| 2 | 不合理的细节 | 不真实的删，因果错的拆开，程度夸张的往回收 |
| 3 | 概括性判断 | 就地换成同篇对应的具体事实；没有对应事实就保留 |
| 4 | 他人评价当支撑 | **不删**，后面接一句自家娃的直接体感 |
| 5 | 无关生活场景 | **多数保留**。只有决定支撑为空、生活场景占满篇幅时才压缩一两处 |

**「就地取材」是这一层现在就能用的关键**——素材库为空也能干活，
因为大多数稿子里细节已经有了，只是没和决定挂上钩。

**不要为了"每句都服务于决定"把闲笔删光**，那会改出一篇干巴巴的说明文。

**这一步依赖 `tables/场景素材.csv`。** 库里是真实的场景描述（用户评论、客服记录、
用户访谈、历史过审句）。**有素材时模型只能挑选和缝合；库为空时只标记位置、不补内容**，
由人来写——这是防编造的关键设计，不要为了让它跑起来而放开。

### 5b · 口语化 → `prompts/口语化.md`

只改措辞、语气、语序、断句，不补内容。

判断方式是**比较**而不是打分：找出偏书面的词组 → 想一个这位妈妈会用的说法 →
换过去明显更像人话才改，差不多就不改。

**实测表现**：硬边界守得住（8 篇改写，新增数字 0、新增竞品名 0、新增功效表述 0），
改出来的东西质量可以（`不得不说适配度不错` → `别说，还真挺合他的`）。
**弱的是改动量分配**——见下方复核要点。

### 复核这一步要看什么

这一步**没有清单，改哪里由模型自己判断**，而这是它最不行的地方
（六种机制实测 F1 0.43–0.45，见 `失败记录.md`）。具体的失败形态：

**改动量分配会反过来。** 实测 8 篇，人工只改 0.9% 的稿子它改了 34.5%；
人工重写 64.8% 的稿子它只改了 3%。**干净的稿子被过度加工、该大改的没动。**

**篇章级问题完全看不见。** 叙事视角混乱、故事线断裂、转折突兀这类，
模型注意力在句子内部。上面那篇人工改 64.8% 的，问题就是视角在邻居娃和自家娃之间跳。

所以复核时：
1. 先看 `改动比例` 自评——**对本来就干净的稿子，高改动比例是危险信号**
2. 通读一遍看篇章级问题，这部分模型帮不上忙
3. 口语化的产出可以抽检；场景化的产出**逐条过**

## 卖点保护：不写 ≠ 不管

**模型对功效宣称和竞品指名有很强的自带先验，规则不写它也会自己动手。**

实测两处，skill 里都没有对应规则，它自己改了：
- `娃体质一直很稳定` → `娃平时状态一直挺稳`，并删掉了后面的支撑场景。
  **人类编辑的方向完全相反——主动加了「听说这个成分能让宝宝保护力更好」**
- `跟风入爱他美` → `跟风买了那款`。**人类编辑原样保留**，
  而爱他美系的当期候选本来就是空的

这推翻了一个我一直以来的假设：**"不写进禁用表就不会被动"。**
对这类内容，不写等于放任模型用自己的默认值。**必须正面占位。**

两条对策：

**一、`tables/核心卖点.csv`** —— 正向清单，写明当期必须保留、不得弱化的表述
（体质、保护力、HMO、长肉、实肉、吸收）。各 prompt 里注明：
**这些是卖点不是风险，不要软化，也不要删掉支撑它们的场景。**

**二、竞品候选为空 = 保持原样。** 表永远会有空行，所以要规定好"空"意味着什么：
本期无统一要求就不要动，**不要自行虚化成「那款」——虚化是策略决定，不是文字问题**。
只有同篇混用多种写法时才需要统一。

（这条改动让回归基线从 28 篇/40 条降到 23 篇/32 条，
少掉的 8 条正是"候选为空却报警"的误报。）

## 表怎么维护

**改表不改码。** 五张表都是 CSV，非技术人员可直接编辑：

| 表 | 维护方 | 什么时候加 |
|---|---|---|
| 红线词 | 合规 | 法规或品牌口径变化时 |
| 卡审词 | 内容 | **每次被平台打回，把打回原因里的词加进去** |
| 竞品表述 | 品牌 | 新增竞品、或当期候选写法调整 |
| 当期策略 | 排期 | 每期主推目标变化 |
| 月龄参考 | 业务 | 当前为通用占位值，**首次使用前必须确认** |
| 效果周期 | 业务 | 每种效果最早多久出现才可信。**当前为通用估值，需业务确认** |

## 已知局限

**前三步不碰语感。** 词表层只管「踩没踩线」，事实层只管「自相矛盾没有」，
定点修正只在清单位置上动。「这句话像不像人说的」是第四步的事。

**「该不该改」的判断没有解决办法。** 语感和场景补充这两类，试过六种机制
（直接判断 / 判断加改写反推 / 显著性比较 / 三信号检出 / 否决器 / 自由发挥），
F1 稳定在 0.43–0.45，没有一种突破。**不要再从这个方向投入**，详见 [失败记录.md](失败记录.md)。

**改写建议会改错地方。** 实测 8 篇：对已经干净的稿子出现过大幅改写（人工只改 0.9%、
模型改了 34.5%），对需要重写的稿子又改得太少（人工改 64.8%、模型只改 3%）。
硬边界守得住，改动量分配不准。

**编造的细节需要专门一层才抓得到。** 事实核查（数字对）、口语化（措辞口语）、
场景化（细节不缺）三层都会放行编造出来的场景——因为编的细节往往很具体。
必须跑第三步细节可信度，跳过它，「一眼假」的内容会原样留到终稿。

**篇章级问题看不见。** 叙事视角混乱、故事线断裂、转折突兀这类，
模型注意力集中在句子内部，实测完全无法发现。这类仍需人工。

## 三档修正的可信度

| 档 | 改哪里由谁决定 | 可信度 | 人工介入 |
|---|---|---|---|
| 词表定点修正 | 词表 | **高**（实测新引入 0、剩余 0）| 抽检 + `verify.py` |
| 事实定点修正 | 事实清单 | 中（实测零编造，取舍模型自定）| 事后扫 `changelog` |
| 口语化 | **模型自己** | 中低（不新增信息，风险可控）| 抽检 |
| 场景化 | **模型自己** | **低**（可能编造）| 逐条过 |

**一个工具同时做检查和改写，用的人容易分不清哪部分能信——所以这张表要给使用者看到。**

## 建议的使用方式

1. 跑 `check.py`，得到词表层清单
2. 跑事实核查，得到事实层清单
3. 两份清单合并，跑**定点修正**——这一步是改稿主力，收益确定
4. 越界检查 + 重跑 `check.py` + 扫一眼 `changelog`
5. 跑**场景化**（先动结构，就地取材优先），逐条过
6. 跑**口语化**（后修措辞），抽检
7. 篇章级问题（视角混乱、故事线断裂）仍需人工——模型看不见这类

**不要跳步。** 润色只改措辞，跳过事实层的代价是事实错误直接进终稿。
