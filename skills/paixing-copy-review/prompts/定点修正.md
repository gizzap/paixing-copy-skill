# 定点修正

按 `check.py` 和事实核查给出的**问题清单**改稿。

与 `改写指引.md` 的根本区别：**改哪里不由你决定，清单已经决定了。**
你只负责在指定位置上把它改好，清单以外的地方一个字都不动。

这一步的风险最低——因为它没有自由度。实测模型在受约束的定点替换上表现可靠
（24 句改写，新增数字 0 处，事实信息零丢失）。

---

## Prompt

> ⚠️ **开始前先检查**：如果下面正文里出现了没被替换的 `{{...}}` 占位符，
> **停下来报错**，不要当成普通文字处理，也不要跳过它继续。


【任务】下面是一篇小红书笔记，以及一份已经确认的问题清单。
请按清单逐条修改，输出修改后的全文。

【最重要的规则】
**只改清单上标出的位置。清单以外的任何一个字都不要动**——
包括你觉得不通顺、不口语、有语病的地方。那些不在本次任务范围内。

【各类问题怎么改】

**竞品表述**：把标出的写法换成清单给的候选词。同一篇里出现多处时，
全篇统一用同一个候选，不要交替使用。

**红线词（病征 / 药效）**：这类词不能出现。
- 能直接删的就删，删完读得通即可
- 删了句子不成立的，改成对**可观察状态**的直接描述，不要用疾病名，
  也不要说奶粉起了什么作用
- 例：「总生病」→ 描述具体状态，或整句删去

**平台卡审词**：换一个说法，意思尽量保留，但不要再用同类的症状式表达。

**事实矛盾**：清单只指出了「两处对不上」，没有说哪一处是错的。

**这是虚构的种草文案，两处数字都是写出来的，不存在"哪个是真的"。
所以你自己选一个改法，不要停下来问。** 选的原则：

1. 改完之后全篇必须自洽——不能修好这处、又和别处对不上
2. 优先保留和产品设定一致的那个（2 段适用 6-12 月龄）
3. 优先改动小的那个

在 `changelog` 里记一句你选了哪个、为什么，供人事后扫一眼。

**只有一种情况要标出来不要自己改**：改动会碰到稿件的设定本身
——人群、宝宝月龄、核心 msg（比如「1 段老客继续喝」）。
那不是文字问题，得写稿的人决定。这种放进 `need_brief_decision`。

【硬性边界】
- 只改清单标出的位置
- 原文已有的事实信息不得丢失



【通用约束】见 `prompts/_通用约束.md`，那里的几条对本步骤同样适用。

【输出】严格返回 JSON，无解释文字，无 Markdown 标记：
{"id":笔记编号,
 "corrected":"修改后的全文",
 "fixes":[{"层":"清单里的层","原文":"改前","改后":"改后","说明":"为什么这么改"}],
 "changelog":[{"原文":"...","我改了哪个":"...","为什么选它":"..."}],
 "need_brief_decision":[{"原文":"...","问题":"...","为什么要写稿人定":"碰到了人群/月龄/msg 设定"}],
 "skipped":[{"原文":"...","为什么没改":"..."}]}

【笔记】
{{正文}}

【问题清单】
{{check.py 的输出 + 事实核查的 issues，逐条列出：层、原文片段、建议}}

---

## 改完必须复查

1. **越界检查**：对比改前改后，所有变动位置必须落在清单标出的范围内。
   有清单外的改动就打回。
2. **重跑 `check.py`**：修正可能引入新的红线词或卡审词。
3. **扫一眼 `changelog`**：事实类模型自己选了改法，不阻塞，但要能追溯。
   `need_brief_decision` 里的才需要写稿人决定。
